## 1. Design approach

1. **Generic `Provider` layer** (identity + verification + listing) with `type`/`subType`/`category` → type-specific data in **extension sub-docs** (not 25 new collections).
2. **Generic `Service`/`Offering`** (bookable/orderable thing) linked to Category + Provider.
3. **Generic `Booking` / `Order` / `Membership` / `EventRegistration`** with type-specific `details`.
4. **Taxonomy in DB** (Category tree) as single source of truth.
5. Keep **T1 (clinical)** data in tenant-scoped collections with field encryption; **T3 (commerce/wellness)** separate to avoid PHI mixing.

## 5. Search index (OpenSearch)
Index public DTO fields only: name, aliases, categories (codes+labels), city/area, geo, rating, openNow, schemes, languages, modes, price bands, verified, tier; **no PHI**; tenant filters server-side; analyzers for Hindi/Hinglish transliteration + synonyms; re-index on provider/taxonomy change; per-type boosts; sponsored slot injection separately labelled.

## 6. Migration plan (safe order)

| Step | Action | Risk control |
|---|---|---|
| 1 | Taxonomy: add `code/aliases/path`, seed canonical specialties; map `Doctor.specialization` → `specialtyCode` (dry-run report first) | Backup, reversible mapping table |
| 2 | Normalise enums (`home`→`home_visit`, `audio/voice/call`→`audio`) with read-compat layer | Dual-read/dual-write period |
| 3 | Introduce `Provider` as view/wrapper over `Facility/Hospital/Clinic` (no destructive merge) | Feature-flag |
| 4 | Add `ProviderTypeConfig` + `ProviderApplication`; keep old `JoinPlatform` for existing types, route new types via config | Parallel run |
| 5 | Add `Service`, `Product`, `Plan`, `Event` models + admin CRUD | Behind flags per city |
| 6 | Search index + public DTO endpoints | Shadow traffic |
| 7 | New cards/detail/profile layouts using section registry | Per-type rollout |
| 8 | Dashboards for new roles (flags) | Pilot with 5–10 providers |
| 9 | Remove hardcoded frontend lists; use `/categories/public` | After parity |

## 8. Testing strategy
- **Contract tests** for public DTOs (no private fields) — extend `dtoLeak.spec.js` ✅
- **Authz matrix** per new route/role (anon, wrong role, wrong tenant, wrong owner, expired, revoked) — `authMatrix.spec.js` ✅ extend
- **State-machine tests** (booking/order/membership/event) incl. concurrency (double booking), idempotency, refund math
- **Config validation tests** (every provider type config valid; required docs present)
- **Search relevance tests** (synonyms, Hinglish, spelling)
- **E2E (Playwright):** join → approve → live → search → book → pay → complete → review
- **Load tests:** search, slots, checkout, event registration spikes
- **Security:** ZAP baseline, upload fuzzing, IDOR sweeps on new endpoints, log-leak checks

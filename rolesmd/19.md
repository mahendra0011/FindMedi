## 1. Quality strategy

| Principle | Meaning |
|---|---|
| **Shift-left** | Spec → testable acceptance criteria → tests along with code |
| **Risk-based** | Zyada testing wahan jahan impact bada: payments, Rx, PHI access, SOS, refunds, auth |
| **Automate the stable, explore the new** | Regression automated; naye features par exploratory testing |
| **Production-like** | Staging = prod config (flags, env, data shapes), anonymised data only |
| **Safety first** | Medical-safety & privacy failures = release blockers (Sev-1) |

## 2. Test pyramid (target mix)

```
          E2E (Playwright)           ~10%   critical journeys only
        Integration (real DB/Redis)  ~25%   API + state machines + queues
     Contract / DTO / Authz tests    ~15%   public DTO, authz matrix, schemas
   Unit (Vitest/Jest)                ~50%   logic, validators, reducers, utils
 + Non-functional: security, performance, a11y, i18n, mobile, resilience (separate tracks)
```

## 4. Unit tests

**Backend:** validators (zod `.strict()`), pricing/fee/GST/coupon calculators, cancellation/refund math, slot generation/overlap, state-machine transitions (guards), Rx schedule rules, substitution logic, taxonomy alias resolution, JWT helpers (alg/iss/aud/typ/kid), HIBP wrapper, safeFetch SSRF rules, DTO mappers, permission checks.
**Frontend:** form validation, price breakup, slot picker logic, filters ↔ URL state, i18n formatting (₹, dates), config-driven wizard rendering from `ProviderTypeConfig`, card components (all states), accessibility attributes.

## 5. Integration tests (real DB — close the SECURITY.md gap)

- Mongo **replica set** (transactions), Redis, OpenSearch (index/search), ClamAV (EICAR), BullMQ workers.
- Flows: booking create → hold → pay webhook → confirm; double-booking concurrency; refund; waitlist promotion; membership renewal; event capacity; Rx order verification; rental lifecycle; provider application → approval → live; document expiry job; retention jobs.
- **Webhook tests:** valid/invalid HMAC, replay, out-of-order, duplicates, partial failures → idempotent.
- **Queue tests:** retries, dead-letter, poison messages.

## 6. Contract & authorization tests

| Suite | What |
|---|---|
| **DTO leak** (`dtoLeak.spec.js` ✅ extend) | Public/provider/patient DTOs never contain `password`, `tokenVersion`, `twoFactorSecret`, full licence no., bank, private phone/email |
| **Authz matrix** (`authMatrix.spec.js` ✅ extend) | For **every new route**: anonymous / wrong role / wrong tenant / wrong object owner / expired / revoked / blocked → DENY; correct → ALLOW |
| **IDOR sweeps** | Iterate IDs across tenants for bookings, orders, records, documents, events, rentals |
| **Schema contract** | OpenAPI ↔ zod; consumer-driven tests for frontend ↔ API |
| **Authz coverage** (`authz:coverage` ✅) | Fails CI if route unclassified |
| **Tenant guard** (`authz:tenant-guard` ✅) | Cross-tenant queries blocked |

## 7. End-to-end (Playwright, real backend in CI/staging)

**Critical journeys (must pass on every release):**
1. Patient signup (OTP) → search → provider detail → book (in-person) → pay → confirmation
2. Video consult: join window, reconnect, end, prescription saved to records
3. Home visit: address, ETA tracking, OTP start/end, review
4. Lab booking + home collection → report upload → patient views
5. Pharmacy: upload Rx → verification → substitution consent → delivery OTP → return
6. Equipment rental: Rx-required → delivery → active → return → deposit refund
7. Gym/yoga membership: trial → purchase → check-in → freeze → renew/cancel
8. Event/camp: register → ticket QR → check-in → results to records
9. Provider join (config-driven) → docs → admin approval → live → first booking
10. Refund/cancellation matrix (patient vs provider side)
11. SOS flow + offline fallback numbers
12. Consent grant/revoke + access log; data export/delete request
13. Family profile switch + dependant booking; guardian consent for minor
14. Admin: KYC review, suspend provider, dispute resolution, moderation action (dual approval)
- Cross-browser: Chromium, WebKit, Firefox (core flows); mobile viewport emulation; **Hindi locale run** for top flows.
- Flake control: network mocking only for third parties; retries ≤ 1; quarantine flaky tests; traces/videos on failure.

## 8. Feature-specific test matrices

### 8.1 Booking engine
| Dimension | Cases |
|---|---|
| Modes | in-person, video, audio, chat, home visit |
| Slots | Last slot, overlapping slots, cross-midnight, DST not applicable (IST) but **timezone/UTC conversions**, holiday, leave, buffer, max-per-slot, advance window |
| Payment | success, fail, pending→success late, duplicate webhook, refund partial/full, wallet+gateway split, coupon limits |
| State | every transition + illegal transitions rejected |
| Concurrency | 50 parallel bookings same slot → exactly capacity succeed |
| Policy snapshot | provider changes policy after booking → old policy honoured |
| Family/guardian | dependant data scoping, minors consent |
| Teleconsult | no-show rules, reconnect, provider no-show compensation |

### 8.2 Pharmacy / Rx
Schedule H/H1/X/NDPS handling · Rx validity (date/doctor/patient mismatch) · reuse prevention · substitution consent · partial fulfilment · cold-chain flags · expiry-limit · return eligibility · delivery OTP failure · H1 register entry · narcotics blocked.

### 8.3 Onboarding/approval
Per provider type: required docs enforced server-side · duplicate detection (phone/PAN/GST/reg no.) · expired docs · needs-info loop · two-person approval for high-risk · probation caps · re-verification expiry job · config version changes mid-draft.

### 8.4 Memberships/recurring
Auto-renew success/fail/retry, mandate revoked, freeze limits, proration refunds, class credits expiry, check-in double-scan, plan upgrade/downgrade.

### 8.5 Events/camps
Capacity/waitlist promotion, cancellation refunds, duplicate registration, check-in offline sync, consent capture required, result delivery to correct record, event cancelled flow.

### 8.6 Search
Relevance (synonyms: Orthopedics/Orthopaedics/"bone doctor"), Hinglish/Hindi, typos, geo-ranking, filters, no-result logging, sponsored labelling, sensitive categories not suggested, index freshness after provider update/suspension.

### 8.7 Notifications
Template rendering per locale, discreet variants, channel fallback, quiet hours, DLT template mapping, opt-out honoured, deep-link validity/expiry, no PHI in payload.

### 8.8 Records & consent
Upload (ClamAV EICAR, bad types, huge files), sharing link expiry/revoke, access log completeness, ABHA linking mock, retention purge, DSR export content & erasure completeness (incl. backups policy).

## 9. Non-functional testing

### 9.1 Security
- **SAST:** Semgrep ✅, CodeQL ✅; **DAST:** OWASP ZAP baseline (staging) + authenticated scan; **dependency:** npm audit ✅, OSV, dependency-review; **secrets:** gitleaks ✅ + pre-commit; **IaC/containers:** Trivy ✅, Checkov.
- **Manual/pen-test:** before R1 public launch (auth, IDOR, payments, uploads, SSRF) and before R4 (sensitive categories).
- **Abuse tests:** rate-limit/lockout, OTP abuse, coupon/referral abuse, review fraud, slot hoarding, SMS pumping.
- **Fuzzing:** API schema-based (schemathesis), upload fuzzing, JSON depth/array bombs.
- **Log-leak tests:** run auth/OTP/reset/booking flows → grep logs/Sentry mock for secrets/PHI.
- **Regression security tests** for every past vuln (`.env` leak guard, JWT `alg`, mass-assignment allowlists).

### 9.2 Performance & load (k6/Artillery)
| Scenario | Target (set after baseline) |
|---|---|
| Search p95 | < 500 ms |
| Slot availability p95 | < 300 ms |
| Booking create+pay p95 | < 1.5 s (excl. gateway) |
| Event registration spike (camp opens) | N concurrent without oversell |
| Notification burst (reminders) | Queue drains within X min |
| Dashboard summary p95 | < 800 ms |
- Also soak tests (4–8 h), spike tests, DB index/explain checks, N+1 detection, memory leaks, queue backlog behaviour.

### 9.3 Resilience / chaos
Kill Redis/Mongo primary/OpenSearch/Kafka/ClamAV/payment gateway timeouts → verify **fail-closed** where required (upload scan, Turnstile strict, authz) and **graceful degradation** elsewhere (read-only mode, cached SOS numbers, queued notifications). Restore drill ✅ (`restore-drill.sh`) quarterly with evidence.

### 9.4 Accessibility
Automated: axe-core in Storybook/Playwright; Lighthouse a11y ≥ 90. Manual: keyboard-only, TalkBack/VoiceOver, 200% zoom, high-contrast/dark, reduced-motion, elder mode (font scale), forms error association, focus management in modals/sheets, colour-blind palette check, captions for video.

### 9.5 i18n/l10n
Pseudo-localisation (text expansion), Hindi + one regional language end-to-end, number/date/currency formats, RTL (Urdu) smoke, font fallbacks for Indic scripts, translated legal pages, notification templates per locale, taxonomy aliases search in Hindi.

### 9.6 Mobile & PWA
Device matrix (low-end Android 2–3 GB, mid, iPhone SE/recent), 3G/Slow 4G/offline throttling, install/PWA manifest, push (foreground/background/killed), background sync, camera upload compression, deep links, upgrade paths, battery/ANR (native shells), SMS OTP autofill.

### 9.7 Compatibility
Browsers (last 2 versions Chrome/Edge/Safari/Firefox + Samsung Internet), WebView versions, screen sizes 360–1440, print styles (invoices/prescriptions), PDF generation (`pdfkit`) — fonts incl. Indic glyphs.

### 9.8 Data & migrations
Dry-run reports + row counts, idempotent scripts, rollback plan, specialty mapping accuracy sampling, enum normalisation dual-read tests, index build impact, backup before/after, **migration rehearsal on staging copy** with production-like volume (synthetic).

## 10. Medical-safety & clinical QA 🆕
- **Clinical advisor review** of: triage/AI flows, red-flag escalation, emergency messaging, drug interaction/allergy warnings, Rx rules, content articles, diet templates, program protocols.
- **Test red-flag scenarios** in AI chat (chest pain, stroke signs, suicidal ideation, pregnancy bleeding) → must escalate with emergency/helpline guidance, no diagnosis/dosing.
- **Content QA:** medical review sign-off, claims policy checks (no cure claims), disclaimers present.
- **Rx/Drug:** LASA, duplicate therapy, pregnancy flags verified with sample data set approved by pharmacist.
- **Incident drills:** wrong-medicine order, provider no-show for critical patient, ambulance delay.

## 11. Release process

| Stage | Gate |
|---|---|
| PR | Lint, unit, authz coverage, DTO leak, SAST/secrets, a11y check on changed components, preview env |
| Merge to main | Integration + contract suites, build, Trivy |
| Staging deploy | Smoke + critical E2E, ZAP baseline, migration dry-run |
| UAT | Business sign-off (§12) |
| Canary prod (5–10%) | Feature flags, monitors: error rate, payment success, latency, crash-free, support tickets |
| Full rollout | If KPIs stable for N hours; rollback plan ready (flag off / revert) |
| Post-release | Sentry review, metrics review, bug triage within 24h |
**Release blockers:** open Sev-1/Sev-2, failing critical E2E, authz/DTO leak failures, migration without rollback, missing legal/consent for new data use.

### 12.3 UAT exit criteria

## 13. Defect management
**Severity:** Sev-1 (safety/privacy/money loss/outage) · Sev-2 (major flow broken, workaround exists) · Sev-3 (minor) · Sev-4 (cosmetic). **SLAs:** Sev-1 immediate (hotfix + postmortem), Sev-2 ≤ 2 days, Sev-3 next sprint.
Fields: steps, expected/actual, env/build, role/persona, logs/trace, screenshots/video, data used (synthetic), impact, owner. Triage twice weekly; root-cause tags (spec gap, regression, data, infra, third-party).

## 14. Metrics

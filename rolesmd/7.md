## 1. Shared dashboard shell (sab roles)

```
Sidebar (role-based) · Top bar (search, notifications, profile, help, language, branch switcher)
Home = Today + KPIs + Tasks + Alerts
Common modules: Profile & Verification · Availability/Calendar · Bookings/Orders · Earnings & Payouts · Reviews · Messages · Documents · Staff (if org) · Reports · Support · Settings & Security
```

### 1.1 Common modules (spec once)

| Module | Features |
|---|---|
| **Home / Today** | Today's bookings/orders, next up, pending actions, alerts (doc expiry, low rating, unanswered chats), KPI tiles (bookings, revenue, rating, response time) |
| **Profile & Verification** | Completeness meter, verification status/timeline, upload/renew docs, expiry alerts, edit (re-verify rules) |
| **Calendar / Availability** | Weekly template, exceptions/leave ✅, slots/capacity, buffer, advance window, sync (Google/iCal) |
| **Bookings / Orders** | List + filters, accept/decline (if approval mode), reschedule, mark complete/no-show, notes, history, export |
| **Messages** | Patient chat (relay), templates, auto-replies, attachments (scanned), escalation |
| **Earnings & Payouts** ✅ | Summary, per-booking breakup, commission ✅, taxes/TDS, payout schedule, statements, holds/disputes, bank details (re-verify on change + step-up) |
| **Reviews** | Ratings, reply, report abusive, insights (themes) |
| **Staff & Access** | Invite, roles/permissions, shifts, deactivate, activity log; **2FA enforced** |
| **Reports/Analytics** | Funnels, revenue, utilisation, cancellations, repeat rate, top services, export (capped + audited ✅) |
| **Support** | Tickets ✅, disputes ✅, knowledge base, priority line |
| **Settings & Security** | Notifications, language, 2FA/passkeys, sessions ✅, API keys (partners), data export |

## 4. Permission matrix (high level)

| Capability | Provider owner | Staff (receptionist) | Practitioner | Finance | Support | Superadmin |
|---|---|---|---|---|---|---|
| Edit profile/services | ✅ | limited | own | ❌ | ❌ | ✅ (audit) |
| View patient PHI | scoped | scoped | assigned only | ❌ | masked | break-glass only |
| Bookings manage | ✅ | ✅ | own | ❌ | view | ✅ |
| Payout/bank | ✅ (step-up) | ❌ | own | ✅ | ❌ | ✅ |
| Export data | ✅ (step-up, capped, audited) | ❌ | ❌ | reports | ❌ | ✅ |
| Staff management | ✅ | ❌ | ❌ | ❌ | ❌ | ✅ |
**Rules:** default deny · tenant + object-level authz · 2FA mandatory for admin/owner/finance/reviewer · every PHI view/export audited · role change → session revoke (tokenVersion).

## 5. Implementation approach
- **Role registry + permission sets** (config) instead of hardcoding per page; sidebar built from permissions.
- Reuse shared modules (calendar, bookings, payouts, reviews, staff) across roles — only domain modules differ.
- Feature flags (Unleash ✅) per role/city for phased rollout.
- New roles need: signup/join type (file 01), approval (file 08), authz manifest entries, tests (authz matrix), audit events.

## 6. Mobile / field-role UX
Phlebotomist, nurse, rider, camp staff → **mobile-first PWA/app**: offline queue, large buttons, geo check-in, camera uploads, OTP handover, SOS.

## 7. KPIs per role (examples)
Doctor: show rate, avg consult time, rating · Lab: TAT, rejection rate · Pharmacy: fill rate, Rx verification time · Gym: retention, occupancy · Yoga: class fill rate · Nurse agency: shift fill, incident rate · Camp organiser: attendance %, referrals · Equipment: utilisation, damage rate.

## 8. Security checklist
- [ ] New roles added to `User.role` enum + authz manifest + tests (`authz:coverage`)
- [ ] Least-privilege defaults; PHI scoped by assignment
- [ ] Mandatory 2FA for privileged roles (`TWO_FACTOR_REQUIRED_ROLES`)
- [ ] Field-level encryption for T1 notes (counselling, rehab, dental/medical notes)
- [ ] Exports capped, audited, step-up
- [ ] Sensitive roles (rehab, mental health, IVF): access reasons + extra audit
- [ ] T3 roles (gym/yoga/store) cannot access medical records

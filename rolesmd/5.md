## 2. Flow A — Slot Booking (extend `BookingModal`)

### 2.1 Steps
1. **Select service & mode** (in-person / video / audio / chat / home visit) → fee preview
2. **Select patient** (self / family member ✅ / other) — age/gender required for some services (e.g., paediatrics), **guardian consent** for minors
3. **Pick date & slot** (real-time slots; hold slot for 5–10 min) · full → **waitlist** ✅
4. **Details:** reason/symptoms (optional), upload reports/prescription (ClamAV ✅), preferred language, **home visit address** (saved addresses ✅ + map pin), insurance/scheme (optional)
5. **Consents:** teleconsultation consent (NMC), data-sharing consent (ABDM ✅), cancellation policy acknowledgement
6. **Review & pay:** breakup (fee + platform fee + GST − coupon/wallet/loyalty), pay (UPI/card/netbanking/wallet/pay-at-clinic if allowed)
7. **Confirmation:** booking ID, calendar add, directions/join link, prep instructions, reminder schedule
8. **Post-booking:** reschedule/cancel, chat with provider (if allowed), pre-visit forms (intake), pay balance

### 2.2 State machine
```
CREATED → SLOT_HELD → PAYMENT_PENDING → CONFIRMED
                 ↘ EXPIRED (hold timeout)        ↘ (provider-approval mode) PENDING_PROVIDER → CONFIRMED / DECLINED
CONFIRMED → RESCHEDULED (new CONFIRMED) | CANCELLED_BY_PATIENT | CANCELLED_BY_PROVIDER
CONFIRMED → CHECKED_IN → IN_PROGRESS → COMPLETED → (REVIEW_PENDING → REVIEWED)
CONFIRMED → NO_SHOW_PATIENT | NO_SHOW_PROVIDER
COMPLETED → FOLLOW_UP_WINDOW (free follow-up) → CLOSED
Any paid state → REFUND_PENDING → REFUNDED / REFUND_REJECTED
```
**Rules:** idempotency key on create/pay (double-click safe) · atomic slot decrement (unique constraint/transaction ✅) · hold released on timeout · server-owned price (no client price) · webhook-confirmed payment only.

### 2.3 Mode-specific
| Mode | Extra |
|---|---|
| **In-person** | Check-in (QR/OTP at clinic), token/queue ✅, ETA/wait time, directions, "I'm late" notify |
| **Video / Audio** | LiveKit room ✅, device test, join window (T−10 → T+30), reconnect, **recording OFF by default**, consent, fallback to audio/phone, no-show rules, prescription after consult (NMC rules) |
| **Chat** | Async window (e.g., 24–48 h), response SLA, closes with summary, escalation to video |
| **Home visit** | Address + geo-fence, visit window (e.g., 2-hr), **provider ETA tracking**, ID badge/QR verify at door, OTP start/end, travel fee, safety (SOS, share-with-family), patient present check, cancel cut-off |

### 2.4 Cancellation & reschedule policy (provider-configurable within platform limits)
| When | Patient cancels | Provider cancels |
|---|---|---|
| > 24 h before | Full refund | Full refund + apology credit/priority rebook |
| 24–4 h | Partial refund (e.g., 50%) | Full refund + compensation (wallet) |
| < 4 h / no-show | No refund (or ≤ 20%) | Full refund + penalty to provider + rating hit |
Reschedule: free once, up to X h before; slot released instantly; fee difference recalculated.
**Medical exceptions** (emergency admission, provider unreachable) → support override.

## 3. Flow B — Request & Quote
```
REQUEST_SUBMITTED → PROVIDER_REVIEW → QUOTE_SENT (price, scope, validity)
 → PATIENT_ACCEPTS → (advance payment) → SCHEDULED → IN_PROGRESS → COMPLETED → (balance payment) → CLOSED
 ↘ DECLINED / EXPIRED / PATIENT_REJECTS (with reason)
```
- Chat thread attached; attachments (prescription/reports) scanned ✅
- Quote has line items, GST, validity (48 h), cancellation terms
- Escrow-like hold: advance held until service started; released after completion (dispute window 48 h)
- Used for: home-nursing plans, dental treatment plans, dialysis intake, equipment install, long-term caregiver.

## 4. Flow C — Order (goods)

### 4.1 Steps
Cart (single vendor or multi-vendor split) → address (✅ saved) → **Rx upload / verify** (Rx-schedule items) → delivery slot/ETA → payment → confirmation → tracking → delivery (OTP) → returns/refund.

### 4.2 Pharmacy order state
```
PLACED → RX_VERIFICATION (if needed) → ACCEPTED_BY_STORE (substitution consent) → PACKED → READY_FOR_PICKUP/OUT_FOR_DELIVERY
→ DELIVERED (OTP) → (RETURN_REQUESTED → RETURN_PICKED → REFUNDED)
 ↘ REJECTED (Rx invalid / out-of-stock / schedule drug) | CANCELLED
```
- **Rx rules:** Schedule H/H1/X → valid Rx mandatory (doctor reg, date, patient name, validity window), H1 register entry, no "quick add"; narcotics not delivered via platform (compliance).
- **Substitution:** show generic alternatives; patient consent per substitution.
- **Cold-chain:** insulin/vaccines — insulated pack, delivery time cap, temperature note, no returns.
- **Partial fulfilment:** some items unavailable → patient chooses accept/cancel.
- **Expiry safety:** min remaining shelf-life shown.
- **Refill subscriptions** (D): auto-reminder → confirm → auto-order.

### 4.3 Non-medicine goods (supplements, devices, skincare, health food)
Same cart; compliance banner (FSSAI/CDSCO), **return window** (7 days sealed; hygiene items non-returnable), warranty for devices, installation scheduling for large devices, recall workflow (batch-based notification).

### 4.4 Delivery partner flow ✅ (extend)
Assign (auto/nearest) → accept → pickup (OTP/photo) → in-transit (live GPS ✅) → drop (OTP) → COD handling (if allowed) → earnings ✅. Multi-pickup batching, cold-bag requirement flag, safety (SOS ✅), failed-delivery reasons.

## 5. Flow D — Recurring / Membership / Program

| Type | Mechanics |
|---|---|
| **Gym / Yoga membership** | Plan (1/3/6/12 mo), joining fee, start date, **freeze** (limited days), upgrade/downgrade, auto-renew (e-mandate/UPI AutoPay), cancellation/refund (pro-rata policy), check-in (QR) |
| **Class pack** | N sessions valid for X days; credits consumed on attendance |
| **Dialysis / physio package** | Recurring weekly slots (✅ `AppointmentSeries`), skip/reschedule rules, package refund pro-rata |
| **Chronic-care program** | Doctor + dietitian + tracking ✅ (ChronicCarePlan); milestones; monthly renewal |
| **Meal subscription** | Weekly menu, skip-day, pause, delivery slot, diet type, allergies |
| **Medicine refill** | Auto-refill cycle, Rx validity check, reminder, confirm |
**State:** `TRIAL → ACTIVE → (FROZEN) → PAST_DUE → (GRACE) → CANCELLED / EXPIRED / RENEWED`.
**Payments:** UPI AutoPay / card mandate with explicit consent, notifications before debit, easy cancel, failed-payment retries.

## 6. Flow E — Event Registration
```
LISTED → REGISTRATION_OPEN → (seats) REGISTERED → REMINDED → CHECKED_IN → ATTENDED → FEEDBACK
 ↘ WAITLISTED → PROMOTED     ↘ CANCELLED / NO_SHOW      EVENT → CANCELLED / RESCHEDULED (notify all, refund)
```
- Seats/capacity, eligibility (age/gender), fee/free, one-registration-per-person, family registration
- **Consent** for data capture in camps (tests/screenings): purpose, who sees results, retention
- QR ticket, calendar add, reminders (T−24h, T−2h), directions/online link
- Camp outputs: **reports/results delivered to patient records** (with consent ✅), referral suggestions, follow-up booking
- Organiser tools: attendee list (masked), check-in app, on-spot registration, capacity alerts, post-event report.
- Free events: anti-abuse (OTP, per-phone limit).

## 7. Flow F — Emergency / Instant
**SOS ✅:** one-tap → location + patient profile (opt) → nearest ambulance/hospital → dispatch → live tracking ✅ → hospital pre-alert → handover.
Rules: **no payment gate** before dispatch; consent for location; fallback to 108/112 call; cancellation without penalty; audit.
**Blood request ✅:** group + component + units + hospital + urgency → matching banks/donors → accept → pickup/delivery → fulfilment.
**Ride ✅:** request → driver match → OTP → trip → payment.

## 8. Flow G — Rental (equipment)
```
REQUESTED → (Rx check for O2/CPAP) → CONFIRMED → DELIVERED+INSTALLED (OTP, photos, condition checklist)
→ ACTIVE (billing per day) → EXTENSION_REQUESTED → RETURN_SCHEDULED → PICKED_UP → INSPECTED → DEPOSIT_REFUNDED (minus damage)
```
Deposit hold, damage policy, sanitisation record, maintenance schedule, emergency replacement, usage instructions/training.

## 9. Payments (common)
- Methods: UPI, cards, netbanking, wallet ✅, pay-at-venue (provider-optional), EMI (P3), insurance/scheme cashless (info + pre-auth ✅), loyalty points ✅, coupons ✅
- **Price breakup:** base + platform fee + taxes (GST on platform fee; service GST per provider category), discounts, wallet
- **Provider payouts** ✅: settlement cycle, commission ✅, TDS, holdbacks for disputes
- **Refunds ✅:** to source/wallet, SLA (3–7 days), partial, auto on provider cancel
- **Failed payments:** retry, slot hold extension (once), payment-pending recovery
- **Fraud:** velocity limits, device checks, coupon abuse, refund abuse, chargeback handling
- **Invoices:** GST-compliant invoice/receipt PDF per booking/order
- Security: server-side price, signed webhooks ✅ + replay protection, idempotency keys, no card data stored ✅

## 11. Post-service
Prescription/report auto-saved to records ✅ (consent) · follow-up reminder · invoice · review prompt · care-plan update ✅ · referral suggestion ✅ · loyalty/rewards ✅ · re-book "same provider".

## 12. Disputes, no-shows, complaints
Report issue (wrong service, no-show, overcharge, quality, harassment) → ticket ✅ (SupportTicket/Dispute) → evidence upload → provider response (48 h) → resolution (refund/credit/penalty/ban) → appeal. Safety incidents (home visit) = priority queue + immediate action.

## 13. Edge cases (must handle)
| Case | Handling |
|---|---|
| Double booking/same slot concurrency | Atomic slot decrement/unique index |
| Payment success but booking failed | Reconcile job + auto-refund/auto-confirm |
| Provider unavailable last-minute | Auto-suggest alternatives + priority rebook + compensation |
| Patient arrives late | Grace window; reschedule/convert to walk-in |
| Network drop in video call | Reconnect/fallback; extend time; partial refund rules |
| Minor / dependent booking | Guardian consent + identity of accompanying adult |
| Time-zone/DST/holiday | Server UTC, local display; holiday calendars |
| Provider changes fee after booking | Locked at booking price |
| Prescription reuse for Rx drugs | Validity + quantity tracking; Rx marked "consumed" |
| Out-of-service area (home visit/delivery) | Pincode/geo-fence check upfront |
| Recurring series disruption | Reschedule single vs series |
| Gym member injured/medical hold | Freeze with doc |
| Event cancelled | Auto-refund + notify + reschedule options |
| Allergy/contraindication | Show warnings in medicine/food orders |

## 14. Metrics
Search→view→book funnel · slot fill rate · no-show % · cancel % by side · reschedule % · payment success % · refund TAT · delivery on-time % · repeat rate · provider response time · review rate.

## 15. Security / compliance checklist
- [ ] Server-owned pricing/eligibility; ignore client amounts
- [ ] Idempotency + webhook HMAC/replay ✅ + atomic state transitions (CAS)
- [ ] Authz on every transition (patient vs provider vs admin) + object-level checks
- [ ] Rx validation; schedule-drug rules; H1 register
- [ ] Uploads scanned; PHI in orders minimised in notifications
- [ ] Location data: consent, minimal retention, purge after trip/visit
- [ ] Rate limits (booking spam, coupon abuse, OTP)
- [ ] Audit log for payment, refund, cancellation, prescription events
- [ ] Teleconsult: NMC guidelines (consent, ID, prescribing limits), recording off by default

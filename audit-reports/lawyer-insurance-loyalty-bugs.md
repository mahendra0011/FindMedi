## [LAW-001] HIGH â€” Loyalty `/admin/*` routes carry no admin guard, including a points-adjustment endpoint
- **Description**: `routes/loyalty.js` (246 lines, 14 routes) registers its administrative surface with `protect` alone: `POST /admin/init-rules`, `GET /admin/earn-rules`, `POST /admin/earn-rule`, `GET /admin/redemptions`, `POST /admin/adjust/:userId`, `GET /admin/reward-catalog`, `POST /admin/reward-catalog`. The file contains **zero** authorisation helpers, so whether these are admin-only depends on inline `req.user.role` checks (10 exist across all 14 routes).
- **Current vs Expected**: Current = the `/admin/` path segment is the only signal that these are privileged, and the guard lives inside each handler. Expected = `authorize('admin')`/`adminOnly` declared on the routes and an explicit admin router mounted under a guarded prefix.
- **Flow**: Loyalty accrual and redemption. `POST /admin/adjust/:userId` changes the points balance of **any** user id; `POST /admin/earn-rule` changes the earning rules for every user. Both are directly monetisable (points are redeemable in the catalog) and both are silent when abused.
- **Root Cause / Logic**: Admin endpoints co-located with user endpoints in one router, relying on path naming plus inline checks â€” the "admin by convention" antipattern.
- **Affected Files**: `routes/loyalty.js` (all seven `/admin/*` registrations), `models/LoyaltyLedger.js`/rules models
- **UI/Frontend Impact**: None visible.
- **Security/Data Risk**: **High.** Unauthorised loyalty-point minting and redemption-data disclosure across tenants â€” a currency-equivalent fraud path with no ledger entry, approval or alert around it.
- **Steps to Reproduce**: With any authenticated non-admin token, call `POST /api/loyalty/admin/adjust/<any userId>` with a points delta and observe the balance change.
- **Suggested Fix / Implementation Plan**: Move `/admin/*` into a separate router mounted behind `adminOnly`, or add `adminOnly` to each route now. Route point adjustments through `services/ledgerService.js` so every change is double-entry and auditable. Alert on large manual adjustments. Remove the inline role checks once the declarative guard exists.
- **Priority**: High
- **Phase**: Phase 1
- **TODOs**:
  - [ ] `adminOnly` on every `/admin/*` loyalty route
  - [ ] Loyalty adjustments written through the ledger
  - [ ] Audit each adjustment with actor and reason
  - [ ] Alert on large or frequent manual adjustments
  - [ ] Split the admin router from the user router

## [LAW-002] Lawyer bookings: 23 routes, zero guards, and money-holding endpoints open to any authenticated user
- **Description**: `routes/lawyerBookings.js` is 979 lines with 23 routes and no authorisation helper. `POST /:id/hold-retainer` â€” a financial hold on a consultation retainer â€” carries only `protect`; `POST /:id/note` (case notes, privileged client material) carries `protect` + `validate(caseNoteSchema)`; and the engagement lifecycle (`/:id/accept`, `/propose-time`, `/decline`, `/start`, `/complete`, `/cancel`, `/reschedule`, `/:id/broadcast-fallback`) is guarded only by inline checks (31 `req.user._id` comparisons suggest ownership checks are intended, but nothing enforces that every route has one).
- **Current vs Expected**: Current = the caller's authority on each transition depends on a handler-level conditional in a 979-line file. - **Flow**: Legal consultation booking â€” matching, engagement, in-session notes, completion and payment. Case notes are privileged material with a regulatory expectation of confidentiality; a leak here is professionally serious, not merely a data breach.
- **Root Cause / Logic**: The same inline pattern as the rest of the audit; the file's size makes a per-handler review impractical, which is why the omission survives.
- **Affected Files**: `routes/lawyerBookings.js` (all 23 registrations), `models/LawyerBooking.js`, `routes/adminLawyers.js`

- **Security/Data Risk**: **High.** Two distinct harms: unauthorised reading of privileged case notes, and unauthorised state changes to a booking that carries money (retainer hold, completion, cancellation) â€” a forged cancellation or completion directly affects the client's legal position.

- **Suggested Fix / Implementation Plan**: Add declarative guards and a shared booking-access assertion used by every `/:id` route; classify transitions by permitted actor; route retainer holds through the ledger with an ownership check; restrict case notes to the engaged parties; add a (route Ã— role) test matrix; split the file.
